What's real and what's staging

  • Real (from the docs): who the processes are, who starts whom, the order of events, what each stage does, and the conditions under which workers become blocked.
  • Staging, to make it visible: processes drawn as people. Distances and speeds. A table of 24 blocks (real tables have thousands). Each blue dot is one result row in scene 5. In scene 7 each dot stands for a group of rows, because drawing every row would be unreadable.
  • Source-code detail, not in the user docs: the per-worker "tuple queues" in shared memory that carry rows to the leader. The user docs only say workers can become blocked when the leader isn't reading tuples fast enough.
