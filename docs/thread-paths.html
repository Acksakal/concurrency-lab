Thread Paths — POSIX threads seen from main()'s point of view

Story

What is a thread, in POSIX terms?
  • Process = the running program: one address space (globals, heap, code) plus at least one thread.
  • Thread = one flow of control inside that process. Each thread has its own ID, stack (local variables), registers, program counter and errno.
  • Everything with an address (globals like count, malloc memory, even another thread's locals if you pass a pointer) is reachable by all threads of the process. That sharing is the power and the danger.
  • When the program starts there is exactly one thread: the one running main() (the initial thread). That's you.
  • Which runnable thread moves next is decided by the scheduler, not by your code. On a multi-core CPU threads even run at the same moment; this page shows one step at a time, which is the standard way to reason about every possible interleaving.

Source: POSIX.1-2024, Base Definitions ch. 3 ("Thread")
